# Token 分词教学场景

核心问题：一个词如何按已有规则变成编号序列？46秒从固定英文词开始，展开基础字符，按三条规则合并相邻片段，检查Token边界，查表得到ID，最后解码还原。

表现：上方刻度保留输入字符，下方片段宽度准确覆盖字符跨度；颜色取自片段起点，合并后边界改变而输入不变。宽度不编码概率。编号沿原顺序出现，指引跟随当前片段。

规则来自 [Hugging Face BPE 教学章节](https://huggingface.co/learn/llm-course/en/chapter6/5) 的已训练示例：u+g、u+n、h+ug。本实现为独立教学代码。词表编号从0起设定，不是生产模型ID。切换0–3条规则代表不同教学版本，绝不是对每个输入重新训练。本节不实现字节级编码、空格处理、中文或特殊Token，不运行语言模型。

反事实实验：固定 hugs，规则0条得到4个Token；规则1条得到3个；规则3条得到hug|s两个Token。字符数一直为4，解码一直为hugs。无匹配的u+n规则在hugs上是无操作。

迁移检验：输入unhug，先预测有几个Token，再解释u|n|h|ug → un|h|ug → un|hug，最后在图中验证[8,9]。错误答案提供中间步骤。

测试命令：node apps/site/learn/tokenization/model.test.mjs。独立黄金值覆盖全部五个词；检查所有规则版本与每0.1秒状态下的字符跨度守恒、顺序、解码、反向跳转、无匹配规则和输入范围。

教学评审：角色、规则、输出均可见；分词和理解/生成明确区分；提供受控实验与新词预测。这是开发者教学适配评审，没有真实学习者效果研究。浏览器验收在发布前补充。

复用请求：用单舞台、浅色细线的可操作图解，解释一个词如何按固定BPE合并规则变成编号。每次只解释当前对象，能暂停、倒退、换词和切换规则版本；输出来源、简化边界和独立验证。
